# Big picture

Purpose: make the LangGraph workflow resumable after a FastAPI/process crash by using SQLite as the durable LangGraph 
checkpointer.

The target behavior is:

    Request
       ↓
    LangGraph
       ↓
    build_search_queries
       ↓
    [checkpoint]
       ↓
    discover_web_sources
       ↓
    [checkpoint]
       ↓
    extract_evidence
       ↓
    [checkpoint]
       ↓
    synthesize_report
       ↓
    [checkpoint]
       ↓
    Completed

If the process dies after extract_evidence:

    FastAPI crashes
          ↓
        restart
          ↓
    same execution_id / thread_id
          ↓
    load latest checkpoint
          ↓
    resume from the interrupted point
          ↓
    synthesize_report

# 5. Update the API invocation

This is the important part.

Instead of:

    final_state = await underwriting_graph.ainvoke(initial_state)

use:

    config = {
        "configurable": {
            "thread_id": initial_state["execution_id"],
        }
    }
    
    final_state = await underwriting_graph.ainvoke(
        initial_state,
        config=config,
    )

Now LangGraph knows:

"This execution belongs to thread X. Persist and recover its checkpoints using that identity."

# 10. What happens after each node?

This is the nice part.

You don't add anything to:

    build_search_queries()
    
        or:
    
    discover_web_sources()

        or:
    
    extract_evidence()

        or:

    synthesize_underwriting_report()

LangGraph handles checkpointing around graph execution.

Your nodes remain focused on business logic:

    Node
     ├── read state
     ├── perform work
     └── return state update

while the graph runtime handles:

    Node result
        ↓
    checkpoint
        ↓
    next node

That separation is exactly what we want.

# 11. One change I recommend to your state

You currently have: execution_status: ExecutionStatus

Keep it.

 But don't confuse this with the checkpoint itself.

For example:

 execution_status = "running", doesn't tell us exactly where the graph stopped.

The checkpoint does that.

Think of them as:

    execution_status
        ↓
    business/execution lifecycle

checkpoint
    ↓
graph recovery state

Later we'll add a proper execution lifecycle around this.
