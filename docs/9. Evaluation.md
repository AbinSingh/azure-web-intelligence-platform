# Deterministic evaluation

# Proposed evaluation approach

| Component                 | Evaluation method                                                                                     | Metric                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------- |
| **1. Search (Tavily)**    | Compare returned URLs against ground-truth URLs. Normalize URLs before comparing.                     | Precision, Recall         |
| **2. Scrape (Firecrawl)** | Check whether expected key facts or phrases from each reference page appear in the extracted content. | Fact extraction pass rate |
| **3. Final output (LLM)** | Compare the generated answer against the ground-truth answer: **Yes / No / Pick list**.               | Accuracy                  |

# 1. Search — URL matching

Example:

Ground truth: URLs A, B, C
Retrieved: URLs A, B, D

Precision = 2/3; Recall = 2/3.

We'll normalize URLs to avoid false mismatches caused by trailing slashes, fragments, and tracking parameters.

# 2. Scrape — expected fact checks

For each URL, save a small set of expected facts or phrases. For example, if a source states that a property is in a 
flood zone, check that the extracted content preserves that fact.

This is easy to automate and avoids subjective scoring. For facts that may be paraphrased, use a small set of acceptable
alternatives rather than exact full-text comparison.

# 3. Final output — ground-truth answer matching

For questions with predefined answer types:

- Yes/No: exact normalized answer match.
- Pick list: compare selected options against the expected set.
- Supporting evidence: additionally check that referenced evidence IDs exist.

For underwriting findings that are free text, we should separately check evidence support rather than require exact wording.

# How I'd organize the dataset

Keep a single JSON dataset with separate expected results for each stage:

    {
      "case_id": "property_001",
      "input": {
        "address": "Example property address",
        "underwriting_questions": [
          "Is the property in a designated flood zone?"
        ]
      },
      "search_ground_truth_urls": [
        "https://example.com/flood-map"
      ],
      "scrape_ground_truth": [
        {
          "url": "https://example.com/flood-map",
          "expected_facts": ["Property is in a designated flood zone"]
        }
      ],
      "answer_ground_truth": [
        {
          "question": "Is the property in a designated flood zone?",
          "answer_type": "yes_no",
          "expected_answer": "yes"
        }
      ]
    }

These are illustrative values, not actual property evidence.

One important distinction: a URL missing from the ground truth isn't necessarily irrelevant, and a ground-truth URL may 
become unavailable. We'll treat URL matching as a benchmark against known relevant sources, not proof that all other 
results are wrong.
