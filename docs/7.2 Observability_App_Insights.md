# In Azure, you can view your agent's telemetry inside Application Insights. The most useful places are 
Live Metrics, Application Map, Performance, Failures, Search, and Logs.

# 1. Where to find your telemetry

Open the Azure portal and navigate to your Application Insights resource.

**Azure Monitor section**	**What you'll see**

Live Metrics	            Near-real-time application activity, request rates, and failures
Application Map	            Your application and its instrumented dependencies
Investigate → Performance	Request durations, slow operations, and dependency performance
Investigate → Failures	    Failed requests, exceptions, and related dependencies
Investigate → Search	    Individual telemetry records and transaction details
Monitoring → Logs	        Query requests, dependencies, traces, exceptions, and custom telemetry using KQL

# 2. Where to see your LangGraph and provider calls

For your Underwriting Intelligence Agent, start with Logs.

In your Application Insights resource:

    - Select Logs.
    - Open a query window.
    - Run the following queries.

# A. Check whether FastAPI requests are arriving
requests
    | where timestamp > ago(30m)
    | order by timestamp desc
    | take 50

This shows incoming requests that Application Insights has collected.

# B. Check external dependency calls
dependencies
    | where timestamp > ago(30m)
    | order by timestamp desc
    | take 50

This can show automatically instrumented outbound calls, such as supported HTTP dependencies. Whether Tavily, Firecrawl, 
and Azure OpenAI appear here depends on the instrumentation and HTTP clients used.

C. Check application logs
traces
    | where timestamp > ago(30m)
    | order by timestamp desc
    | take 100

This displays collected diagnostic log records.

D. Check exceptions
exceptions
    | where timestamp > ago(30m)
    | order by timestamp desc
    | take 50

This helps you investigate captured exceptions and their details.

Note: Data may take a little time to appear. If the queries return no results, first confirm that the application is 
running, telemetry initialization succeeded, and the correct Application Insights connection string is configured.

# 3. Will you see individual LangGraph nodes automatically?

Not necessarily. This is an important distinction.

Azure Monitor's automatic FastAPI instrumentation can capture incoming requests and supported dependencies. It does not automatically understand every business-level operation in your custom LangGraph workflow.

For example, you want to see:

    underwriting.execute
        |
        ├── langgraph.node.build_search_queries
        |
        ├── langgraph.node.discover_web_sources
        |       └── tavily.search
        |
        ├── langgraph.node.extract_evidence
        |       └── firecrawl.scrape
        |
        └── langgraph.node.synthesize_underwriting_report
                └── azure_openai.generate

These named operations require the custom tracing instrumentation we are adding to your application.

Once the spans are exported correctly, you can inspect individual operations and their durations in the transaction 
details and related trace views.

# 4. What about token usage and retries?

These also require explicit instrumentation in your current implementation.

    Information	                    How it gets recorded
    LLM input/output tokens	        Capture usage metadata from the Azure OpenAI response
    Retry attempts	                Record each attempt in your recovery function
    Execution outcome	            Record the final LangGraph status
    Evidence count	                Add an attribute to the execution span
    Individual node duration	    Create a span around each graph node

Once exported, you can query supported telemetry fields in Logs. The exact table and field depend on whether the 
information is recorded as a trace, span, log, metric, or custom event.

# 5. What I recommend doing right now

Before instrumenting every node, verify the basic connection:

    - Start your FastAPI application.
    - Send a request to your existing underwriting endpoint.
    - Open Application Insights → Live Metrics to check for incoming activity.
    - Open Logs and run the requests query above.
    - Check the dependencies query to see which external calls are being collected automatically.

Live Metrics is designed for near-real-time monitoring; Logs is better for inspecting stored telemetry.

Once basic telemetry is visible, the next step is to add custom spans for LangGraph nodes and Tavily, Firecrawl, and 
Azure OpenAI operations. That is what will make your agent's complete execution traceable rather than merely showing that an HTTP request occurred.
