# Big picture

Right now, the LangGraph state is essentially a collection of fields passed between nodes.

For enterprise use, we want the state to become the single source of truth for one underwriting research execution.

It should clearly represent:

    Request
       ↓
    Research Plan
       ↓
    Search Results
       ↓
    Evidence
       ↓
    Insights
       ↓
    Final Report

This will make the system easier to extend later with recovery, persistence, human approval, observability, and evaluation.


# 1. Update app/graph/state.py

    Why add execution_id now?

This is important.

Every underwriting request should eventually have a unique execution identifier:

    execution_id
         ↓
        logs
         ↓
        state
         ↓
      database
         ↓
    human review
         ↓
    audit trail

We'll use this heavily when we implement observability and persistence later.

# 2. Update app/graph/nodes.py

We should now make the nodes operate explicitly on the state rather than creating loosely structured intermediate data.

Important improvement here

We now preserve errors inside:

"errors": errors instead of only doing: print(...)

That's important because later our Recovery, Observability, and Evaluation layers can inspect those failures.

# 5. Result of this branch

The important change is architectural, not functional.

Previously:

    API
     ↓
    Graph
     ↓
    Some dictionaries
     ↓
    Report

Now:

                    UnderwritingState
                           │
             ┌─────────────┼──────────────┐
             ↓             ↓              ↓
          Request       Research       Execution
             │             │           Metadata
             ↓             ↓              ↓
          Queries      Evidence         Errors
             │             │
             └──────┬──────┘
                    ↓
                 Insights
                    ↓
                  Report

Every node reads from and returns the same typed execution state.

That gives us the foundation for the next branches.
