# Big picture

The goal is to prevent a single external failure from killing the entire underwriting run.

Today:

    Tavily
      ↓
    Firecrawl fails
      ↓
    Workflow fails

# After this branch:

Tavily / Firecrawl / Azure
        ↓
   transient failure?
      ↙       ↘
    retry    permanent
     ↓           ↓
   continue   record error
        \       /
         ↓     ↓
       workflow
         ↓
   partial/complete report

We will add:

- Timeouts
- Bounded retries
- Exponential backoff
- Graceful Firecrawl failures
- Explicit error recording
- LLM retry for transient failures
- No infinite retry loops

We will not add persistence or recovery-from-process-crash yet. That belongs to the next infrastructure stages.

- Exponential backoff is a strategy for retrying a failed API request where you wait progressively longer between each retry.

Instead of:

    Fail → retry immediately → fail → retry immediately → ...

you do:

    Fail → wait 1s → retry → wait 2s → retry → wait 4s → retry → wait 8s...
