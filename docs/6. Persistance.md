# Big picture

Introduce durable LangGraph checkpointing so every successful graph transition can be recovered and resumed after 
process failure.

The architecture should be:

                    FastAPI
                       │
                       ▼
                LangGraph Graph
                       │
                       │ thread_id
                       ▼
              ┌─────────────────┐
              │   Checkpointer  │
              └────────┬────────┘
                       │
              ┌────────┴────────┐
              │                 │
          Development       Production
          SQLite            PostgreSQL


# I would also introduce an execution lifecycle
Separately from the raw LangGraph checkpoint, maintain a lightweight execution concept:

    PENDING
       ↓
    RUNNING
       ↓
    WAITING_FOR_HUMAN
       ↓
    RUNNING
       ↓
    COMPLETED

and failure states:

    FAILED
    INTERRUPTED
    CANCELLED

This is useful because the checkpoint store answers: "Where was the graph?"

while execution metadata answers: "What is happening with this underwriting job?"

Those are different concerns.

# What I recommend we implement next

Goal:

Add durable LangGraph checkpointing with SQLite first, while keeping the checkpointer interface replaceable so 
production can move to PostgreSQL without changing graph/business logic.

Implementation sequence:

    4.1
    Add LangGraph checkpointer abstraction
            ↓
    4.2

            ↓
    4.3
