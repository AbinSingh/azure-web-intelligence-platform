# 1. Metrics vs. Telemetry

Telemetry is the overall data your application generates to understand its behavior, including traces, metrics, and logs.

Metrics are numerical measurements aggregated over time. They help answer questions such as: How many underwriting 
executions failed? How long do they take? Which provider is slow?

| Type        | Purpose                                           | Example                                                  |
| ----------- | ------------------------------------------------- | -------------------------------------------------------- |
| **Traces**  | Follow an individual execution across operations. | Why did this underwriting run take 12 seconds?           |
| **Metrics** | Monitor overall performance and trends.           | What is the average execution latency across 1,000 runs? |
| **Logs**    | Record events and diagnostic details.             | Why did a Firecrawl request fail?                        |

Your existing OpenTelemetry and Application Insights implementation already provides tracing and some request/dependency measurements. 
Prometheus would add a dedicated approach to collecting and querying aggregated application metrics.

# 2. Top 5 Metrics for Your Underwriting Agent

| Metric                                  | Purpose                                                                          |
| --------------------------------------- | -------------------------------------------------------------------------------- |
| **1. End-to-End Execution Duration**    | Monitor underwriting latency and identify slow executions.                       |
| **2. Execution Success/Failure Rate**   | Measure reliability and detect increases in failed underwriting runs.            |
| **3. Provider Latency**                 | Compare Tavily, Firecrawl, and Azure OpenAI performance to identify bottlenecks. |
| **4. Evidence Extraction Success Rate** | Measure how effectively discovered sources produce usable evidence.              |
| **5. LLM Token Usage and Cost**         | Monitor model consumption and control AI operating costs.                        |

These five metrics cover the core operational concerns: performance, reliability, research quality, and cost.

# 3. How Prometheus Fits In

Prometheus is a monitoring system that collects numerical metrics from applications, stores time-series data, 
and lets you query it using PromQL.

For your agent, the flow would look like this:

    Underwriting Agent
           │
           │ Exposes application metrics
           ▼
       Prometheus
           │
           │ Stores and queries metrics
           ▼
         Grafana
           │
           ▼
    Dashboards, Trends and Alerts

For example, Prometheus could help you monitor:

    - The 95th-percentile underwriting execution duration.
    - The percentage of executions that fail.
    - Average latency for each external provider.
    - Evidence extraction success rates.
    - Total LLM tokens consumed over time.

One important distinction: Prometheus does not automatically understand your business metrics. You must instrument the 
application to expose them. For token usage and cost, for instance, your agent must capture token counts from the Azure OpenAI response.

My recommendation: Skip the Prometheus/Grafana implementation for now. Your existing tracing foundation is valuable; 
when you revisit metrics, prioritize these five and use traces to investigate individual executions behind metric anomalies.
